# 流式门谱台（Flow Gate Bench）

一个本地运行的流式细胞术门控工作台：**每个群体定义、父群体关系、仪器补偿与通道变换都版本化、可重放**。
用 Rust + Axum + SQLite 交付，Web UI 为零构建步骤的原生 HTML/CSS/JS。

页面包含：

- 双通道投影散点（叠加当前多边形门，可点击追加顶点、用顶点表修正）；
- 单通道直方分布（父群作用域内，门内事件叠加高亮）；
- 门系树、事件数、父子百分比（空父群显示“不可定义”）；
- 补偿矩阵 / 变换版本切换、门修正后的版本重放与**下游失效传播**；
- 任意两个运行分支按**事件身份**比较进入 / 退出 / 共同差异；
- 运行记录导出 JSON、清空数据库后重新导入并自动复核。

## 安装与演示

```bash
cargo fetch --locked
cargo test --locked
cargo run --locked -- --listen 127.0.0.1:5582
```

浏览器打开 <http://127.0.0.1:5582>，应看到标题 **流式门谱台**。

可选参数：

- `--listen 127.0.0.1:5582`：监听地址（默认同）。
- `--db flow_gate_bench.sqlite`：SQLite 文件路径（默认当前目录）。首次启动若库为空，
  会自动写入固定 fixture 并从根完成首次重放。

测试共 21 项：几何半开规则单元测试、引擎端到端测试、HTTP 接口测试。

## 数据口径（务必先读）

1. **原始强度**：每个事件固定 4 个通道 `FSC_A, SSC_A, CD3, CD19`，
   刻度 0–1000；两个仪器批次 `B1`(FC-Lab-01) 与 `B2`(FC-Lab-02)。
   固定 fixture 共 384 个事件，身份为 `E0001..E0384`，由确定性 LCG 加手工边界事件生成，
   任何机器、任意次清空重建结果一致（见 `src/model.rs`）。
2. **补偿矩阵**：`out[row] = Σ_c coeff[out][in] * raw[in]`。矩阵的行、列**必须由通道名
   与数据通道唯一对应**，与矩阵在文件里的物理排列无关。fixture 内置：
   - `C1` 单位补偿；`C2` 含 CD19→CD3 串色；
   - `C3` 通道顺序重排的单位补偿（验证“按名称、不按位置”，结果必须与 `C1` 完全相同）；
   - `C4` 故意缺少 `SSC_A`：选择它时返回 422 且**不产生任何新运行**，绝不按位置继续乘。
   重复通道、未知通道、行列数不符同样拒绝。
3. **通道变换**：在补偿之后逐通道执行。`T1` 全部线性；`T2` 对信号通道 CD3/CD19 使用
   `log10(1+x)` 并线性映射回 0–1000 刻度（散射通道仍线性），因此同一套多边形坐标
   可直接在两种变换空间比较。
4. **多边形门在“补偿后 + 变换后”的坐标空间判定**。每次运行都记录
   `gate_version_id / comp_id / transform_id`，因此旧结果永远可按原版本复现。
5. **统一半开几何**（`src/geometry.rs`）：顶点先归一化为逆时针。
   - 共享边内部：两个逆时针多边形沿共享边方向相反，只有沿该边“下行”
     （水平边则为“左行”）的一方认领，**共享边事件恰好计一次，绝不双计**；
   - 共享顶点：采用半开端点约定，可能归一方也可能两方都不计，**但任何顶点都不可能
     同时进入两个门**（测试对竖边、水平边、对角分割、相切角逐一断言）；
   - 退化多边形（少于 3 个有效顶点或零面积）在保存新版本时即被拒绝。
6. **百分比**：`100 * 子事件数 / 父事件数`。当父群事件数为 0 时百分比为
   `null`（不可定义），UI 显示“不可定义（父群为空）”，**绝不写成 0**。
   fixture 中 `RARE`（大细胞内零命中）的子群 `ULTRA` 就是空父群示例。
7. **失效传播**：
   - 修正某个门：生成新门版本；该群体及其整个下游子树的旧当前运行标记为
     `invalid`（**历史计数保留可审计，但不再挂为当前、不再显示成当前数**），
     然后只为受影响子树生成新运行；未受影响的分支（如改 SMALL 时的 BIG 支）
     原运行与计数原样保留。
   - 切换补偿或变换：整棵树旧运行全部 `invalid` 后从根重放。
   - `invalid` 运行的计数仍在库里并可参与分支差异，但页面以红色“失效”徽标明确区分。

## 典型操作

1. 在“门系树与计数”中点选群体，右侧散点显示当前门（绿实线）与编辑中的顶点（黄虚线）。
2. 点击画布或顶点表修正多边形，填写说明，点“保存为新门版本并重放”。
3. 树中 T / B 等子群的新运行自动出现，旧运行标红为“失效”；用节点上的“查看全部运行”
   下拉或底部“分支差异”选择新旧两个运行，查看进入/退出事件身份。
4. 顶部切换补偿（试 `C3` 看计数不变；试 `C4` 看 422）或变换（`T2`）触发整树重放。
5. 点“导出运行记录”得到 `flow-gate-bench-bundle.json`（含完整 fixture 快照、
   版本引用和每个运行的事件身份成员集合，包括 invalid 历史）。
6. 删除/更换 SQLite 文件或点“恢复固定 fixture”可清空；用“清空并导入复核”选择导出文件，
   系统清库→导入→从根重放→将每个当前运行的事件身份集合与导出逐一比对，
   报告每个群体的 `expected_count / replayed_count` 与差异身份。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 通道、批次、门系、门版本、补偿/变换定义与当前运行摘要（含百分比） |
| GET | `/api/scatter?x=&y=&run_id=&limit=` | 某运行空间（或当前空间）双通道投影 |
| GET | `/api/histogram?channel=&bins=&run_id=&parent_run_id=` | 父作用域直方 |
| GET | `/api/runs?population_id=` | 群体全部运行（含 invalid 历史） |
| GET | `/api/diff?a=&b=` | 两运行按事件身份的 entered/exited/both |
| POST | `/api/gates/edit` | `{population_id, note, polygon}` 新门版本 + 子树重放 |
| POST | `/api/replay/comp` / `/api/replay/transform` | `{id}` 版本切换整树重放 |
| POST | `/api/reseed` | 清空并恢复固定 fixture |
| GET | `/api/export` | 下载 bundle JSON |
| POST | `/api/import` | 上传 bundle，清空重导并复核 |

## 目录结构

```
src/
  main.rs       入口与参数解析
  web.rs        Axum 路由与静态资源
  db.rs         SQLite schema / 播种 / 清空
  engine.rs     补偿、变换、半开门评估、失效传播、差异、导出导入复核
  geometry.rs   统一半开点-多边形几何（含单元测试）
  model.rs      领域类型与固定 fixture（确定性事件生成）
static/         index.html / app.js / style.css（编译进二进制）
tests/          engine.rs（10 项端到端）、http.rs（4 项 HTTP 验收）
```

SQLite 表：`events / batches / channels / transforms / compensations / populations /
gate_versions / runs / run_members / current_runs / meta`。`runs` 保存全部历史
（含 invalid），`current_runs` 只指向每个群体当前有效的一次运行。
